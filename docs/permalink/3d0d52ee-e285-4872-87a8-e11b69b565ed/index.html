Software Multipliers For Young Ladies

Programming November 11, 2026 11:35 of narration 3 min read

Listen · 11:35

MP3

If you make your web application command driven,
where the previous commands send text to the current.

Then you can experience your application functionality in console,
before you even have a GUI.

If you were working on a visual programming language,
you could make all the boxes you connect commands.

And then you could use them raw, in a command line program,
you can chain several commands with pipe character.

Tell your AI to use EventSourcing,
and you will be able to redo/undo too, for free.

Visual programming where you connect ports of boxes,
is an alternative to GUI actually.

Take image editing for example, you are applying filters and operations,
you can do that in visual programming, and you get free replay.

Just change the image, and send it down the pipeline again,
throw in video processing too, video is just many more images.

And processing video one frame at a time,
is the only reasonable way to do it.

Even if you loaded gigabytes into memory,
processing frame by frame is the only way to do it right.

Web Desktops are an amazing way,
to give your users multiple complex windows, billing, and user management…

Like on a real desktop user can move the windows out of the way,
and choose which one is on top, or even minimize and restore a window.

And it is not just windows, you often see draggable panels,
especially in complex applications, and that is called a dockview.

It primarily gives your user the ability to re-arrange the layout,
of your application, which means it is no longer something on your todo.

And you can provide the users with pre-set layouts,
minimalist, default, custom1, custom2, custom3, and layout is licked.

Now you only worry what goes into the little panels,
and you should treat those little things as program plugins.

Your AI will thank you, a lot, because it will be able to focus on one thing,
and it will know it it decoupled, somewhat separate and self contained.

You can connect plugins together, and say that this plugin provides X and Y,
and requires A and B.

And now you have an AI on your hands, it is an ancient model,
called a goal solver, where you give AI a goal and what it requires….

And it sets of on a quest to find the matching provides, and also satisfy their,
requirements with other provides, creating a long chain.

You can say GOAL:
file manager.

And a blank dockview will begin splitting it self,
into little panels.

And start populating them, with plugins like directory tree, icon view,
file properties, file search, file templates, and recently edited, and locations.

A goal solver,
truly is a form or artificial intelligence.

Best for last, you can start with pixels, you don’t need to use boring old UI,
and this does not mean that you must create a computer game.

You can use 3d graphics to map out complex trees,
and then interact with them, travel through them, or rotate trees.

And, you can use pixel art,
AI will be more than happy to help you make a UI kit, with cute animations even.

And it is easy to make layout engines,
you don’t even have to imagine splitting a square up and down.

But nesting either a vertical container or a horizontal container,
For an icon bar, you use a horizontal container that will lay thing out one after another.

To make two rows of icons, you first use a vertical container,
and then before you add icons, you place two horizontal containers inside it.

So the vertical container, now positions two horizontal containers,
that can hold two rows of icons.

It is all,
very easy.
